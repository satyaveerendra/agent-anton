# docs/decisions.md — judgment calls, one line each

Format: `ID · decision · why (alternative considered)`. IDs M/S/C refer to the Step-0
review; A-items are derivative assumptions made while applying it; X-items were
considered and declined. Phase-time decisions append below with a `P<n>-` prefix.

## Step 0 — review-driven spec changes (2026-08-27)

- M1 · Escalation is an explicit invocation mode (`--escalate`, default off) on both `discover` and `replay`; §9 defines the off-fallback for every trigger and §11's triggers apply only when enabled · §9 and §11 gave opposite terminal behaviour for the same condition, so AW-4 and AW-5 could not both be green; an unattended production call must never block on a human unless the caller said one exists (alternative: escalation always on, rejected — breaks AW-4/AW-6 and the unattended contract).
- M2 · Four statuses: `SUCCESS | BUSINESS_OUTCOME | BLOCKED | FAILED`; `FailureDetail.kind` and `BlockedDetail.kind`; exit code is a pure function of the result (0/10/20/30/40) with a unit test over every combination · "needs a human" is neither an outcome nor a failure — filing it under FAILED is the glossary's conflation one level up, and a policy Deny is an audit event distinct from "the page 500'd" (alternative: three arms + `FailureKind` for everything — fewer arms but the caller must read a sub-field to learn "resumable by a human").
- M3 · `ReplayResult` gains `outcome_step_id`, `outcome_detector_id`, `outcome_detail`; `StepResult.detectors_fired` · AW-2 asserted a step name the schema could not express; the caller gets the observed message for VALIDATION_ERROR too.
- M4 · One `Redactor` at every sink, scrubbing known values + `redact_value_patterns` + masked-element text, applied at snapshot build time; failure page snapshot is redacted `SemanticSnapshot` JSON · redaction was field-name based while AW-4 asserts a value-level property; the SSN sits in a nameless cell; for a bank the model call is the leak, not the transcript file (alternative: post-hoc regex over files — protects the repo, not the customer).
- M5 · Dead-end = unchanged state hash across repeated identical actions (3) or any non-READ actions (6); READ never counts · the URL+landmark rule fired on every ≥3-field form and on consecutive reads, aborting the sub-account discovery mid-form.
- M6 · `discover --approve-risky` for caller consent; `APPROVAL` intervention kind with Approve once / Deny under `--escalate`; lease edge `PAUSED → AGENT_ACTIVE` · §8 promised a console "confirm" the console did not have, and phase 5 depended on phase 6; a one-shot token keeps the model's action an agent action so the distiller records it RISKY.
- S1 · AW-7 (five legs) + `open_subaccount.json` hand-authored in phase 4; `VALIDATION_ERROR` is a BUSINESS_OUTCOME · the brief's own example flow, three of its six runtime conditions and its one "your call, justify it" decision were built and never proven.
- S2 · Detectors evaluated on every 250 ms tick with the postcondition; first hit wins; detector hit never retries · "poll to timeout, then look" cost a full 8 s per business outcome and made `slow` flaky against the timeout.
- S3 · Injection table with trigger route + arity; `expire` on first authenticated `GET /member/<id>`; `slow` fixed `SLOW_MS` on the shell route only; `err500` sticky on `/subaccount/new`; `deny` sticky on the confirm POST · "on next request" was undefined and could fire at login; AWs must be deterministic by construction.
- S4 · AW-3 has expire / modal / slow legs; §18 enumerates the AW per runtime condition · the brief names six conditions; the spec built five and verified two.
- S5 · `requires_flows` + `preconditions` on the artifact; engine establishes them via profile flows as pseudo-step `__preconditions__`; discovery logs in through the replay engine before the first model turn; `$secret:` tokens in `act.value`; gate denies literal-equals-secret · login was specified twice and the model typed the password; now credentials never pass through the model and login is not duplicated into every capability.
- S6 · `run_flow` recovery re-localizes via the same `resume_point()` (furthest satisfied signature) that human hand-back uses; login honours `?next=` · "re-attempt the step" after re-login cannot work from `/search`; one resume path instead of two.
- S7 · `OutputType` (no secrets), `normalize`, coercion per type, `outputs: dict[str, str|int|float|bool]`; AW-1 compares `Decimal` · "typed outputs" returned strings; the test, not the engine, was doing the typing.
- S8 · Outcome-space closure validator (step + inherited profile codes ⊆ `business_outcomes`); detectors discriminated on `arm` · a global detector could emit a code the artifact never declared; payload/arm mismatches validated fine and failed at runtime.
- S9 · Locators are a discriminated union with `frame_path`; tier 2 bounded to `right_of_label` / `below_label` / `row_cell` over snapshot geometry only; `tag` → `control_type`; fingerprint strictness per tier · `spec: dict` on the centerpiece; open-ended geometry was the largest effort sink; DOM relations leaked through the surface seam.
- S10 · `$param:` binding into every emitted string; AW-1b replays a second member id · otherwise the distilled artifact is a macro for 204817 — the exact thing §4's docstring forbids.
- S11 · `finish(outputs: {name: ref})`; §10 split into loop / recording / distillation / limits contracts; `TurnRecord` model · the brief's "heart" was one paragraph and output→element attribution was heuristic.
- S12 · Effective risk = max(policy, step); `requires_approval` derived; URL-of-commit rule (`/subaccount/review$`, CLICK or any PRESS) + label rule; labels pinned in §6; RISKY ⇒ `retries == 0` · three risk sources with no precedence let an artifact downgrade; a label regex gated the harmless submit and missed Enter; re-clicking Confirm is the duplicate-transaction bug.
- S13 · Glob semantics defined; `/member/**`; policy ceiling ∩ profile; `${ANTON_TARGET_ORIGIN}` + `--policy`; post-navigation URL check · `/member/*` excluded the sub-account routes; two allowlists had no precedence; the fixture's free port would have made every AW exit 30.
- S14 · Console is an in-process daemon thread that never touches Playwright; the owning thread pumps with `page.wait_for_timeout(250)`; default port 7071; `/api/state` + action endpoints · sync Playwright is thread-affine and `time.sleep` starves `expose_binding`; macOS AirPlay squats 7000; AW-5 needs a machine seam.
- S15 · `InterventionRequest` defined; `InterventionRecord.kind/resolution/timestamps`; `StepResult.status` + `resolution{tier, candidate_index, source, fingerprint_ok}`; `ReplayResult.tenant_id/overlay_id/artifact_sha256`; lease `ABANDONED` · AW-6 asserted locator provenance the result could not carry; "nobody came" had no representation.
- S16 (trimmed) · Discovery hand-back re-observes and continues; human actions are evidence with `origin: human`; a run containing a takeover distills to `draft`; distiller merging of human actions is a REPORT §7 next step · the brief requires recording, not folding into the artifact; merging is real scope.
- S17 · Typed `StepOverride` / `TenantOverlay` with `route_prefix`, `output_overrides`, `success`; `url_matches` strips the active prefix; extraction validated against `OutputSpec` · the untyped overlay could not reach the three things beta actually changes, so AW-6 was unreachable.
- S18 · `MaskSpec{ladder, applies_to, required}`; unresolved required mask ⇒ blanked frame + `mask_unresolved`; AW-6 asserts none on beta · Playwright silently takes an unmasked screenshot when a mask locator does not resolve, and PNGs are invisible to the grep.
- S19 · `make verify-evidence` scans `evidence/ artifacts/ runs/` for every seeded SSN/DOB, the fake password and `sk-ant-` · the public repo is the leak surface; the only prior value check was one SSN in one `runs/` dir.
- S20 · `--outputs-file` (0600, never under `runs/`); stdout/`result.json` always redacted with `redacted_view: true`; `account_number` sensitive, `savings_balance` not · the result said "present for caller" while the only caller was stdout; the demo balance must be readable in evidence, an account identifier need not be.
- S21 · `field_value` / `checked` predicates required on FILL/SELECT; `ActError` typed and treated as a t=0 miss; global RECOVERABLE detectors evaluated pre-act · vacuous FILL postconditions hid lost keystrokes and broke re-localization; a landmark behind a modal counted as visible.
- S22 · `ANTON_ARTIFACT_DIR` selects the artifacts under test; discovery gate checks `provenance.discovery_run_id` and sha256 equality; hand-authored artifacts move to `tests/fixtures/` after phase 5 · "passes unmodified" was unverifiable while phase 4 and phase 5 wrote the same path.
- S23 · REPORT §6 seeded with the guardrail model's limits · the brief's heading is "…and its limits"; a §6 that lists only mechanisms reads as marketing.
- S24 · AW-1 tier assertion scoped to targeted steps; fixtures `approved`; Makefile lists every verify target; §13 flag table; `retries` vs `max_attempts` defined; `LEASE_NOT_HELD` is not a policy violation and gate events carry lease state · each was a gate that could not go green as worded.
- C1 · `ANTON_MODEL` default `claude-sonnet-5` · newer and cheaper than `claude-sonnet-4-6` ($2/$10 vs $3/$15); adaptive thinking, no prefill — verified against the current model table.
- C2 · Phase 7 is explicitly first to cut; if cut, `TenantOverlay` + loader tests remain as the schema-level proof · criterion #5 is design-graded and the brief says not to build multi-tenant plumbing; the stretch demo is worth one bounded session, not the tail of the project.

- C4 · AW-5's human scenario is the risky Confirm needing a person (replay with `--escalate`, no consent); the sabotaged-ladder fixture is dropped; the phase-6 discovery demo uses the APPROVAL intervention · a banker-recognizable reason that exercises takeover + recorder + resume; the "modal before its detector exists" trigger would not have stuck the model.

## Step 0 — derivative assumptions (veto any)

- A1 · Operator **Deny** on a replay APPROVAL intervention → `BLOCKED(APPROVAL_DENIED)`, exit 40; in discovery the model gets the tool result "denied by operator" and continues · keeps every "a human decided / must decide" outcome under one status the caller already handles (alternatives: business outcome `APPROVAL_DENIED` exit 10; FAILED with a new kind). **Pending author confirmation.**
- A2 · AW-4 runs `open_subaccount` with `err500` sticky on `GET /member/<id>/subaccount/new`, after the member page (SSN) was observed, and asserts a positive `***` signal · `err500` on the member page would have failed the run before any PII page rendered, making the redaction grep vacuous.
- A3 · Target app keeps runtime-created sub-accounts in memory and serves `GET /__state/member/<id>` only when `ANTON_TARGET_DEBUG=1` (fixture-only) · AW-7a's "no new sub-account" needs a machine-checkable source; seed data stays read-only.
- A4 · `--escalate-timeout` default 600 s · the panel's proposal; long enough for a live demo, short enough that an unattended run ends.
- A5 · `DiscoveryResult` model + `discover` exit codes (0/20/30/40) · the CLI needed something to print; kept minimal and parallel to `ReplayResult`.
- A6 · Precondition establishment is a pseudo-step `__preconditions__` with its own `StepResult` · gives `FailureDetail.step_id` and AW-3b's "exactly one step's recoveries" a home when the modal fires before step 1.
- A7 · Invalid `--param` values exit 2 before any browser launches · the conventional usage-error code; not a replay outcome.
- A8 · `slow` delays the member shell route only (not the iframe pane) · shell + pane at 5 s each would exceed the 8 s step timeout and turn a "wait absorbs it" test into a retry test.
- A9 · `BusinessDetector.detail_locator` feeds `outcome_detail` · M3's `outcome_detail` needed a declared source.
- A10 · AW-7e covers C12's draft refusal · one deterministic leg proves the rule.
- A11 · `.DS_Store` added to `.gitignore` · macOS had already created one in the root.
