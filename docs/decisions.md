# docs/decisions.md — judgment calls, one line each

Format: `ID · decision · why (alternative considered)`. IDs M/S/C refer to the Step-0
review; A-items are derivative assumptions made while applying it; X-items were
considered and declined. Phase-time decisions append below with a `P<n>-` prefix.

## Step 0 — review-driven spec changes (2026-08-27)

- M1 · Escalation is an explicit invocation mode (`--escalate`, default off) on both `discover` and `replay`; §9 defines the off-fallback for every trigger and §11's triggers apply only when enabled · §9 and §11 gave opposite terminal behaviour for the same condition, so AW-4 and AW-5 could not both be green; an unattended production call must never block on a human unless the caller said one exists (alternative: escalation always on, rejected — breaks AW-4/AW-6 and the unattended contract).
- M2 · Four statuses: `SUCCESS | BUSINESS_OUTCOME | BLOCKED | FAILED`; `FailureDetail.kind` and `BlockedDetail.kind`; exit code is a pure function of the result (0/10/20/30/40) with a unit test over every combination · "needs a human" is neither an outcome nor a failure — filing it under FAILED is the glossary's conflation one level up, and a policy Deny is an audit event distinct from "the page 500'd" (alternative: three arms + `FailureKind` for everything — fewer arms but the caller must read a sub-field to learn "resumable by a human").
- M3 · `ReplayResult` gains `outcome_step_id`, `outcome_detector_id`, `outcome_detail`; `StepResult.detectors_fired` · AW-2 asserted a step name the schema could not express; the caller gets the observed message for VALIDATION_ERROR too.
- M4 · One `Redactor` at every sink, scrubbing known values + `redact_value_patterns` + masked-element text, applied at snapshot build time; failure page snapshot is redacted `SemanticSnapshot` JSON · redaction was field-name based while AW-4 asserts a value-level property; the SSN sits in a nameless cell; for a bank the model call is the leak, not the transcript file (alternative: post-hoc regex over files — protects the repo, not the customer).
- M5 · Dead-end = unchanged state hash across repeated identical actions (3) or any non-READ actions (6); READ never counts · the URL+landmark rule fired on every ≥3-field form and on consecutive reads, aborting the sub-account discovery mid-form.
- M6 · `discover --approve-risky` for caller consent; `APPROVAL` intervention kind with Approve once / Deny under `--escalate`; lease edge `PAUSED → AGENT_ACTIVE` · §8 promised a console "confirm" the console did not have, and phase 5 depended on phase 6; a one-shot token keeps the model's action an agent action so the distiller records it RISKY.
- S1 · AW-7 (five legs) + `open_subaccount.json` hand-authored in phase 4; `VALIDATION_ERROR` is a BUSINESS_OUTCOME · the brief's own example flow, three of its six runtime conditions and its one "your call, justify it" decision were built and never proven.
- S2 · Detectors evaluated on every 250 ms tick with the postcondition; first hit wins; detector hit never retries · "poll to timeout, then look" cost a full 8 s per business outcome and made `slow` flaky against the timeout.
- S3 · Injection table with trigger route + arity; `expire` on first authenticated `GET /member/<id>`; `slow` fixed `SLOW_MS` on the shell route only; `err500` sticky on `/subaccount/new`; `deny` sticky on the confirm POST · "on next request" was undefined and could fire at login; AWs must be deterministic by construction.
- S4 · AW-3 has expire / modal / slow legs; §18 enumerates the AW per runtime condition · the brief names six conditions; the spec built five and verified two.
- S5 · `requires_flows` + `preconditions` on the artifact; engine establishes them via profile flows as pseudo-step `__preconditions__`; discovery logs in through the replay engine before the first model turn; `$secret:` tokens in `act.value`; gate denies literal-equals-secret · login was specified twice and the model typed the password; now credentials never pass through the model and login is not duplicated into every capability.
- S6 · `run_flow` recovery re-localizes via the same `resume_point()` (furthest satisfied signature) that human hand-back uses; login honours `?next=` · "re-attempt the step" after re-login cannot work from `/search`; one resume path instead of two.
- S7 · `OutputType` (no secrets), `normalize`, coercion per type, `outputs: dict[str, str|int|float|bool]`; AW-1 compares `Decimal` · "typed outputs" returned strings; the test, not the engine, was doing the typing.
- S8 · Outcome-space closure validator (step + inherited profile codes ⊆ `business_outcomes`); detectors discriminated on `arm` · a global detector could emit a code the artifact never declared; payload/arm mismatches validated fine and failed at runtime.
- S9 · Locators are a discriminated union with `frame_path`; tier 2 bounded to `right_of_label` / `below_label` / `row_cell` over snapshot geometry only; `tag` → `control_type`; fingerprint strictness per tier · `spec: dict` on the centerpiece; open-ended geometry was the largest effort sink; DOM relations leaked through the surface seam.

- P1-8 · `ReplayResult`/`DiscoveryResult` validators enforce arm exclusivity (outputs iff SUCCESS, failure iff FAILED, blocked iff BLOCKED, outcome fields iff BUSINESS_OUTCOME) · makes `exit_code()` total: no combination can reach an undefined exit.

- P2-4 · The search form is a GET to `/search`; `?member_id=` redirects (302) to `/member/<id>` · a plain HTML form with no JS is the legacy-app shape; §6's "Submit → GET /member/<id>" is honoured through one redirect that Playwright follows.

- P2-7 · `?inject=<name>` arms the injection process-wide with the same arity as `INJECT=` · one flag, one meaning, either way (SPEC §6 "both supported so replay demos are one flag").
- P2-8 · Runtime sub-account numbers are `7<member_id><seq:03d>` and render as type "Savings (sub)" · deterministic, unique, and the "Savings" row anchor stays unique per §6.
- P2-9 · Last-name search renders a results table of links · §6 says "(or last name)"; kept minimal, no AW depends on it.
- P2-10 · `/__state/member/<id>` is registered outside the tenant prefix, only when `--debug-state`/`ANTON_TARGET_DEBUG=1`, and exempt from the login guard · it is fixture plumbing, outside the allowlist by construction (§16 gate test) and off in every demo.
- P2-11 · Static files are served under the tenant prefix (`static_url_path=f"{prefix}/static"`) · beta's pages linked `/portal/static/…`, which 404'd; an unprefixed `/static` route on beta would also have contradicted "unprefixed routes return 404".

- P2-13 · `err500` fires on `GET` only (the pinned arity); `next` values starting with `//` are rejected; the not-found pane body is chrome-free · small hardening from the phase-2 audit.

## Phase 3 — surface + policy (2026-08-28)

- P3-1 · Tier-1/2 resolution runs over the REDACTED snapshot (per §7); `ResolvedElement.role/name` are re-read from the unredacted enumeration so fingerprints and `name_matches` see live names · anchors and control names survive redaction by rule (3), so resolution works on what the model and the logs see.
- P3-2 · `ConcreteAction.value_kind` (`literal|param|secret`) added to the §7 tuple; `None` is treated as literal and SELECT/PRESS values are checked too · the gate cannot distinguish "literal equals a secret" (SECRET_LITERAL) from a resolved `SecretRef` without provenance; nothing else can carry it.
- P3-3 · `Surface.url()` and `Surface.path()` (prefix-stripped) added to the §7 protocol; `ResolvedElement.text` carries the snapshot's (redacted) text for `text_snippet` fingerprints · the post-navigation check and the engine's `UrlMatches` need the path; the walk stays surface-independent with no side channel.
- P3-4 · Glob helpers (`glob_covers`/`glob_match`) live in `policy/gate.py`; the loader re-exports them · `loader` imports `PolicyConfig` from `gate`, so the reverse import was a cycle; the allowlist semantics belong to policy anyway.
- P3-5 · Visibility is per element and recursive: intersects the TOP viewport AND own-document `elementFromPoint(centre)` is the element or a descendant AND, for every ancestor document, `elementFromPoint` at the element's centre mapped into that document is the containing iframe (batched hit tests, one round-trip per parent/child pair) · SPEC §7 verbatim; a partial top-frame overlay hides exactly the pane elements it covers.
- P3-6 · Tier 3 (`bbox`) resolves geometrically to the smallest visible snapshot box containing the normalized centre, not a live `elementFromPoint` · keeps every tier surface-independent; the walk still returns a live handle by ref.
- P3-7 · Mask ladders are resolved on the UNREDACTED enumeration before rule (3) runs; the value cells inside them are then scrubbed · masks target values by their labels, and the labels are anchors either way.
- P3-8 · Accessible name order: `aria-label` → for controls: `<label for>` / wrapping label / preceding cell in the same row / previous sibling text / parent direct text → placeholder/title/name; for everything else: own text · the target app has no `<label for>`; the preceding cell is what a human reads.
- P3-9 · Static elements are enumerated only when they carry DIRECT text (a `<td>` holding only a `<span>` yields the span, not both) · keeps the ≤60-element digest free of nested duplicates while every banner/heading/cell text stays matchable.
- P3-10 · `act()`: CLICK/PRESS use `no_wait_after=True`, NAVIGATE uses `wait_until="commit"`, SELECT tries the option label then the value · §7 "does not wait for a resulting navigation"; the engine polls.
- P3-11 · Screenshot masks are opaque `position:fixed` overlays injected into the element's own frame and removed after capture; the fail-closed image is a stdlib-generated solid PNG · works inside the iframe with no extra dependency.
- P3-12 · Native dialogs are always dismissed (never accepted) and logged with a scrubbed message · a `confirm()` during a RISKY step must not commit silently; REPORT §6 lists it as a limit.
- P3-13 · `resume_point()` lands with the engine in phase 4 · it evaluates postconditions, which need the predicate evaluator the engine owns.
- P3-14 · `screenshot()` keeps its own enumeration local — the observed snapshot/raw pair stays paired — and a driver error while injecting a mask fails closed (solid PNG + `mask_unresolved{mask_id: "*"}`) · refs are positional; re-pairing them across two enumerations could hand the engine the wrong live element.
- P3-15 · `label_context` is computed for static cells too (preceding cell in the row, else the header cell above in the column) so rule (3) scrubs value cells with NO mask ladder; a mask region always wins over the anchor exemption; anchors are short (≤ 40 chars) label texts · with masks as the only mechanism, an unresolved mask silently leaked a DOB into observation logs.
- P3-16 · Landmarks are enumerated even without direct text (empty text, box only) · §7 lists landmarks unconditionally.
- P3-17 · Relative NAVIGATE URLs are joined against the current page inside the gate; risky-rule `url_matches` sees the prefix-stripped path via `GateContext.route_prefix` · artifacts carry origin-relative URLs and §4 `UrlMatches` strips the prefix, so the two rule families must see the same path.
- P3-18 · `resolve_ladder_until()` polls observe()+walk on a 250 ms tick until a deadline · SPEC §9 "ladder resolution is polled within the step budget"; the pane iframe lands a tick after the shell. `row_cell` keeps `col_header` mandatory (§4 validator); label anchors are never interactive controls.
- P3-19 · Target-app markup facts for artifact authors: §6 "headings" are bold `<span>`s (role `text`, control_type `span`); the accounts header row is `<td>` (role `cell`), which `row_cell` accepts (CELL_ROLES); the pane iframe has a 1 px border, accounted for via `clientLeft/clientTop` · so hand-authored ladders use `text`/`cell` roles, never `heading`/`columnheader`.
- P3-20 · Static-cell label context = preceding cell text AND the column header above (joined), except that cells in a table's FIRST row never take context from a neighbour · the "Balance" header sits right of "Account No." and was being scrubbed — which silently broke `row_cell`; headers/labels are anchors, values take context.

## Phase 4 — replay first

- P4-1 · `Surface.read` gained a third attr `"checked"` ("true"/"false") — alternative: read `checked` through `handle.evaluate` from the engine — rejected because the engine must never touch a driver handle directly; the seam stays the only place that knows Playwright (SPEC §7).
- P4-2 · `Surface.last_snapshot()` added to the protocol — alternative: have the engine re-observe after the ladder resolves — rejected: SPEC §9 says the pre-act observation is *the snapshot on which the ladder resolved*, and a second observe could see a different page (AW-4's frame_path assertion depends on it).
- P4-3 · `locate.resume_point(steps, success, holds, start)` takes a predicate-evaluation callback instead of a snapshot — alternative: pass the snapshot and import the evaluator into locate — rejected to keep `locate` driver-free and import-cycle-free (`predicates` imports `locate`); the same function serves human hand-back in phase 6 (§11: one resume path).
- P4-4 · Terminal outcomes are raised as `_Terminal` exceptions (`_Failed` / `_Business` / `_Blocked`) from wherever they are decided and assembled into `ReplayResult` in exactly one place (`run_replay`) — alternative: return status tuples up the call chain — rejected: the status ↔ exit-code mapping must live in one place, and flows/recoveries nest three deep.
- P4-5 · The entry navigation is a gated action like any other (NAVIGATE through `ActionGate.check` + the post-navigation check) — alternative: navigate before the gate exists — rejected: an off-allowlist `--url` must be a POLICY_VIOLATION, not a silent page load.
- P4-6 · Browser viewport pinned to 1280×900 for every replay; the hand-authored tier-3 boxes were measured at that size on the recorded app — alternative: Playwright's 1280×720 default — rejected only because the sub-account form's confirm button sits below 720 px in the recorded layout; the number is a constant in `engine.py`, not a magic value in artifacts.
- P4-7 · Headed by default (SPEC §2); `--headless` / `ANTON_HEADLESS=1` for CI and the acceptance fixture — alternative: headless default — rejected: the demo and AW-5b need a visible browser.
- P4-8 · `api.invoke` returns the REDACTED view (`redacted_view=True`); raw sensitive outputs exist only in `--outputs-file` (mode 0600) — alternative: return raw outputs to the Python caller — rejected: SPEC §5/§12 say only the outputs file carries raw sensitive values; a Python caller that wants them passes `outputs_file`.
- P4-9 · A driver/engine crash inside the run (any non-`_Terminal` exception) becomes FAILED `CHECKPOINT_MISS` with an `engine_error` event instead of a traceback — alternative: let it propagate — rejected: SPEC §19 AW-2 forbids tracebacks and the run directory must always carry a result.json; the exception type/text is logged so nothing is hidden.
